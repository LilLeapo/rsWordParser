# CASE-LAYOUT-01 · image/layout instruction document

## Goal

Create a synthetic Chinese layout manual through Word UI. This is the fourth of
five required theme documents. It focuses on inline and floating drawings,
text wrapping, captions, text boxes, and symbol content.

## Stable anchors

- `CASE-LAYOUT-00`: identity marker.
- `CASE-LAYOUT-INLINE`: paragraph containing an inline image and caption.
- `CASE-LAYOUT-FLOAT`: paragraph before a floating image with square wrapping.
- `CASE-LAYOUT-TEXTBOX`: marker immediately before a text box.
- `CASE-LAYOUT-SYMBOL`: paragraph containing a symbol or formula.
- `CASE-LAYOUT-END`: final body marker.

## Planned checkpoints

1. `C01`: title/heading/body skeleton.
2. `C02`: two uses of image resources, inline drawing, floating drawing with
   square wrap, and Word captions.
3. `C03`: Word text box with unique anchor and symbol/formula content.
4. `C04`: direct formatting plus tracked edit/comment interaction.
5. `C05`: close/reopen, final Save As, independent XML checks, and Rust read.

## Creation/oracle rules

- All DOCX body/structure and image insertion must happen in Word 16.112.3 UI.
- The two 120x120 PNG files are local pre-made assets; no DOCX is generated by
  script.
- Independent zip/XML checks verify drawing types, anchors/wrap, caption fields,
  text box content, media relationships, and symbol/math content.
- Rust verification proves package open, visible text markers, and no-edit byte
  fidelity. Drawing/caption semantics not projected by the M1 model are recorded
  as `NOT_IMPLEMENTED`, not as pass/fail.
