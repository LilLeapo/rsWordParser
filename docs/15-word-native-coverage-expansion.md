# Word 原生能力覆盖扩展清单

日期：2026-09-10。基于当前代码、测试文件、第一轮报告和第二轮设计做静态交叉检查。用户希望更广泛覆盖 Word 功能，最终用途以投标编写为主。

执行分支继续使用 `docs/codex-test-handoff`。本文件接续 docs/13、docs/14；已经通过且证据充分的项目直接引用，不重复制作。以下“补测”不是声称仓库完全没有该领域测试，而是要求核对功能边界和真实 Word 生命周期证据。

## 1. 先回答“原生支持”到底是哪一层

逐功能分开报告以下能力，不能压缩成一个支持/不支持勾选框：

1. 包能打开，不损坏未知内容。
2. 内核能读取语义和关系，native API 能输出。
3. 公开 API 能创建或修改，错误路径原子回滚。
4. 保存结果能被 Word 打开，显示与预期相符。
5. Word 中该对象仍可作为原生对象操作，而不只是预览图片或缓存文本。
6. Word 执行更新、继续编辑、另存后结果仍正确，内核再次读取也正确。

不承诺内核实现 Word 布局、宏执行、字段求值或任意嵌入应用。具体功能先核实规范和代码。读取缓存不等于重新计算；保留 XML 不等于可编辑；截图正确不等于对象数据正确。

## 2. 本次静态调查的直接依据

- `edit/mod.rs` 已声明大量公开操作，包括 ToggleCheckbox、SetFormText、SetSdtContent、SetChartData、SetThemeFonts/Colors、UpsertStyle、RestartNumbering、SetWatermark、SetMathTokens、SetDrawingGeometry/Wrap/ZOrder、SetSources 等。
- `tests/note_sdt_ops.rs`、`sdt.rs` 已有锁定/绑定控件拒绝和内容修改测试，不应再笼统称控件完全未实现。
- `tests/chart_ops.rs::edit_03_set_chart_data_patches_cached_texts_only` 明确只检查图表缓存文本修改，并保留引用公式。必须另测 Word“编辑数据/刷新”行为；目前不能据此断言内嵌工作簿一定同步。
- `tests/twin_sync.rs` 已验证 Choice 文本框同步 VML Fallback。需要实际 Word 对象和支持条件下其他 Word build 的验证。
- `span/field/instr.rs` 明确只做 tokenizer，不解释 IF、不计算 SUM(ABOVE)、不解析 MERGEFIELD 数据源。测试应分开缓存、指令、Word 更新结果。
- `tests/save_options.rs` 已覆盖主题、样式、编号、保护、水印等结构写回；真实 Word 行为仍需独立证据。
- `tests/real_edits.rs`、`resolve_fixtures.rs` 和既有真实语料可能已覆盖部分需求，执行前先检索并引用，不把所有项目记为零覆盖。

## 6. 每类都要走的生命周期

```text
Word 创建并保存 A
  → 独立结构检查 + 内核/native 语义断言
  → 公开 API 修改并保存 B
  → Word 打开 B，记录修复提示和显示
  → 原生对象操作（继续编号 / 编辑图表数据 / 编辑公式 / 修改控件）
  → 显式更新字段或相关对象，另存 C
  → 内核读取 C，对比预期
```

按独立副本区分“打开但不更新”“显式更新”“继续编辑”三条路线，避免 Word 自动修改掩盖引擎原始产物。A/B 的字节保真在 Word 改写 B 之前验证。C 只比较适用语义和结构，不要求 Word 输出与 B 字节一致。

需要外部 Excel/Windows 等能力的步骤先记录依赖，完成本机可做部分。截图必须核实文件身份；操作回执和 DOCX 哈希绑定。不要凭截图猜 XML，也不要凭 XML 猜最终页面效果。

## 7. 用组合覆盖，而不是一份“万能文档”

在每类最小例子通过后，至少组合以下高风险对：

- 内容控件 × 修订 × 表格单元格。
- 多级编号 × 样式更新 × 章节复制。
- 页眉页脚 × 分节删除 × 水印 × 页码重启。
- 图表 × 内嵌工作簿 × Word 刷新。
- 共享图片 × 多 part × 删除对象和资源清理。
- 文本框 × Choice/Fallback × 超链接或公式。
- 书签/交叉引用 × 跨 run 替换 × 修订接受拒绝。
- 缺省格式 × 显式零/false × 主题和样式继承。

按 feature × 操作 × 内容流 × 保存路线建立覆盖矩阵。用 pairwise 选择减少重复，再对上述明确高风险组做三因素组合；不要将 pairwise 当成所有交互都已证明。
