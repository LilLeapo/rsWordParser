# 第二轮增量：面向投标编写的真实格式测试

日期：2026-09-10。接续 [第二轮任务](13-round2-semantic-e2e-test-tasks.md)，使用同一 `docs/codex-test-handoff` 分支。用户提供真实招标文件作为格式参考，最终产品侧重编写投标文件。不要重启已完成任务。

## 1. 参考依据与范围

先读 [格式参考与夹具说明](../fixtures/tender/guangzhou-it-2025/README.md)，其中列出了原文件哈希、实际 XML 观察值、三项新增回归测试和未验证范围。

原件只在提供文件的机器上，未通过 Git 分发；另一台 Mac 可先执行已提交的合成夹具和下面的 Word 复现，不因缺原件停止。需要对原件执行全量验证时，再取得原文件并校验哈希，不能把重建文件当原件。

该原件的 480 twip 首行缩进是物理长度（24 磅），不是 firstLineChars=200。即使某种字体下视觉接近“两字符”，两条路径仍须分别测试。原件没有正文直接 spacing，不能为方便造 expected 而补上 spacing=0。

来源事实与派生测试必须分列：本文件提到的评分表、报价表、响应表等是投标应用场景设计，不意味着已经在原件中逐张完成业务分类。

## 2. 新增优先用例

| ID | 来源或设计动机 | 创建与操作 | 必须验证 |
| --- | --- | --- | --- |
| BID-STYLE-01 | 511 处首行 firstLine=480 | Word 中制作普通正文、替换供应商占位文字 | 长度型缩进 raw/effective/API；文字变长后缩进仍为 480，不能变字符单位 |
| BID-STYLE-02 | null3 稀疏样式且无 basedOn | 运行已提交夹具；UI 新建对应稀疏样式版本 | 不按样式名猜角色；实际继承来源明确；UI 自动增加 basedOn 时作为另一种变体 |
| BID-STYLE-03 | 无直接 spacing + lines 网格 | 设置接近原文件的页面网格，段落不直接设间距 | 缺省与有效值分开，linePitch=312 不自动等同固定行距 15.6 磅 |
| BID-STYLE-04 | 字号/居中/加粗分布 | 合成封面、章标题、正文三种格式 | 字号半磅单位；直接格式与样式并存；不能按字号自动改语义 |
| BID-FILL-01 | 单下划线文本常见 | 合成签字、日期、单位名称栏，在下划线 run 内填入长短文字 | 下划线范围、空白和字体保留；不是自动创建表单域 |
| BID-FILL-02 | 模板字段会被拆 run | 同一占位符跨不同 run，填入中文、数字和英文名称 | 查找跨 run，指定匹配范围；格式继承明确，多匹配不静默选首个 |
| BID-TABLE-01 | 原件含 40 行×4 gridCol 表 | Word UI 建长响应表，持续填入长文本、增行 | 精确行列归属；保存重开；分页观察与结构断言分开 |
| BID-TABLE-02 | gridSpan 为 2/3/5 | Word UI 建分组表头及合并响应栏 | 物理 cell 数与逻辑列数区分；编辑某格不改邻格 |
| BID-TABLE-03 | 无 val 的 vMerge 续接 | 已提交 XML 夹具 + Word UI 建跨行组别栏 | 缺省 vMerge=continue；restart/continue 不误判；删除/增行后几何合法 |
| BID-TABLE-04 | auto 宽度、无 tblLayout | 报价表由短金额改成长说明，再保存 | 不把 auto=0 当零宽；不擅自补 fixed 布局；Word 可能重排，保留观察 |
| BID-TABLE-05 | 原件无 tblHeader | baseline 不含重复表头，再显式开启另存 | 缺失与开启两种案例分列，不把“看似表头”当真实重复表头 |
| BID-PAGE-01 | 原件页面/边距/网格 | A4 尺寸、上下 1440、左右 1800、header851/footer992，能精确输入时设置 | XML 实际舍入值与期望对照；编辑正文不改变节属性 |
| BID-RESPONSE-01 | 投标响应编写 | 根据合成条款填“满足/偏离/说明”，与重复编号内容区分 | 目标单元格身份稳定；无关条款及编号原样；不能全局粗暴替换 |
| BID-ASSEMBLE-01 | 模板扩充 | 复制响应章节、增删人员/报价行、插入附件占位段落 | 样式引用、表格合并、节归属和编号保持正确，语义差异只在授权范围 |

每个 GUI 用例使用合成业务内容。通过 computer use 实际创建并保存 Word 文档；程序夹具和 UI 文档分别归档。原文件并未包含所有派生功能，不必强求逐字逐对象复制原件。

## 3. 与第二轮主任务接合

R2-01 驱动必须输出这些用例的 raw/effective/native/compat 值以及 part、表格坐标和锚点。继承/主题/网格的预期必须来自独立属性来源分析，不得从生产 Resolver 输出倒灌 golden。

R2-04 使用公开 EditOp 执行填充/属性修改/表格编辑；如产品入口为 Agent/CLI，再追加该入口同一操作的结果对照。每次保留预期、实际、错误码、修改范围和保存回验。未知或不支持的操作明确拒绝并验证无副作用。

R2-05 增加针对以下错误的负向或变异测试：480 当字符单位、缺省间距当零、null3 被忽略、auto 宽度当零、vMerge 无 val 当无合并、段落插入重写节网格、模板填充遗漏跨 run 的一半、重复条款误替换。
