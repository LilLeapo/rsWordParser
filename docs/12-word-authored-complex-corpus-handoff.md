# 增量交接：通过 Word 界面创建复杂真实语料

日期：2026-09-09。接收者：正在执行 [全面测试交接](11-codex-test-handoff.md) 的另一台 Mac 上的 Codex + computer use。

## 1. 用户最新要求与接续方式

用户确认新增一条测试主线：通过 computer use 在 Word 中创建 DOCX，亲手添加各种内容，文档越复杂越好，然后查看并验证项目的读取效果。旧版交接已经在执行，本文件是增量要求，不替换原计划。

继续已运行的测试和检查点，不重新开始。优先补入真实 Word 创建的复杂语料，复用已有驱动、判据、失败产物和报告。开始前记录当前受测代码指纹；旧交接中的提交号和编译错误只是历史快照，不得据此回退当前代码。

本文件与原交接通过 docs/codex-test-handoff 分支分发。同步文档时不要直接把该分支的旧代码作为受测版本。可 fetch 后提取指定文档，或在干净的独立分支 cherry-pick 对应文档提交；不得覆盖目标机器正在运行的源码修改。

“亲手创建”指 Codex 使用 computer use 操作 Word 桌面界面，不是要求用户逐项手工操作。复杂 Word 语料的正文与结构必须由 Word UI 创建，不能用 Python、XML 拼装、DOCX 库或脚本批量生成文件后冒充 Word 创建。允许通过 UI 输入或粘贴准备好的合成文本，以及插入本地测试图片；图片可以预先制作，但不能代替 Word 中的结构操作。

不得只交付测试建议。实际创建、保存、读取、比较、回验，并提交可复现证据。操作原始文件、账号及对外发送的边界沿用原交接。

## 2. 目标产物与复杂度要求

制作以下至少五个主题文档，以及一个把主要功能组合起来的综合文档。数量只是起点；先完成具有真实结构的复杂案例，再根据发现扩展。

| 文档 | 重点组合 | 必须验证的交互 |
| --- | --- | --- |
| 中文长篇技术报告 | 标题体系、目录、多节、页眉页脚、页码、脚注尾注、横向附录 | 标题与目录字段；节和页眉页脚继承；长段落跨页 |
| 复杂投标报价书 | 多级编号、宽表、合并单元格、单元格内列表与图片、不同页面方向 | 表格内段落格式、合并关系、图片与单元格锚定 |
| 协作修订合同 | 批注、插入删除修订、超链接、书签、交叉引用 | 修订范围与文字格式；引用目标；批注锚点 |
| 图文排版说明书 | 行内与浮动图片、环绕、题注、文本框、公式或符号 | 绘图锚点、尺寸与资源关系；文本流与对象顺序 |
| Unicode 与格式压力文档 | 中英混排、emoji、组合字符、双向文字、空白、Tab、换行、样式继承 | UTF-16 边界、直接格式与样式、同一段多 run |
| 综合复杂文档 | 上述主要功能交叉组合，并有多轮真实编辑历史 | 多次保存重开后读取稳定；局部编辑不破坏其他结构 |

综合文档以约 30～60 页作为初始目标，不把页数当硬性通过条件。要同时覆盖结构多样性和交叉嵌套；不得靠重复粘贴同一段落充数。Word 实际版本不支持某项功能时记录 UI 证据、原因和替代覆盖，继续其他项目，不把替代项算原功能通过。

阶段性范围建议：至少 4 种标题层级、3 个真实 section、多个页眉页脚配置、2 种编号层级、5 种不同结构表格、行内及浮动图片、书签与链接、字段与引用、批注与修订。精确结构以保存后的独立检查为准。

不要为了达到数量引入不受 Word 支持的结构。不要求 Mac Word 具备某个特定按钮、公式编辑方式或 Strict 导出选项；先检查当前版本能力。不能通过改 XML 把缺失的 Word UI 能力伪装成已完成。

## 3. 先设计答案，再操作 Word

每个用例开始前写 manifest：功能目标、操作计划、预期语义、验证方式和稳定定位标识。采用纯合成业务内容，不使用真实个人、客户或投标数据。

正文中安排可见唯一锚点，例如 CASE-TABLE-03、CASE-REV-02，便于 UI 查找与解析结果对应。对特殊场景避免锚点影响预期格式；确有影响时使用前后文定位。不要依赖 NodeId、页码或 run 序号作为跨保存的稳定标识。

为每个 GUI 动作或小批次记录：

```text
step_id
目标锚点
Word 中实际执行的操作
预期文本 / 属性 / 结构变化
保存检查点文件及 SHA-256
截图或 UI 观察证据
独立 XML 检查结果
内核读取结果与差异
```

Word 显示是观察证据，不单独决定结构答案：手打“1.”不等于编号列表，打粗体大字不等于标题样式，手打页码不等于 PAGE 字段，空格对齐不等于 Tab，分页符不等于分节符。使用 Word 对应功能，并检查实际持久化的结构。

## 4. 逐步增复杂，而不是只保存最终巨型文档

每个主题文档按阶段保存独立版本：

1. C00：最小正文和唯一锚点。
2. C01：样式、直接格式和文本边界。
3. C02：列表、表格、图片等主题结构。
4. C03：分节、引用或嵌套组合。
5. C04：批注、修订或多轮编辑历史。
6. C05：关闭重开、必要字段更新后的最终版本。

并非每个主题都必须加入全部功能，但综合文档必须形成完整阶段链。每阶段均执行内核读取，不等最终版才第一次测试。另存为独立路径，确认自动保存或云同步不会改写已经归档的检查点。

增加长编辑历史：对同一位置连续做约 20～50 个有意义的操作，例如拆分合并段落、局部设格式再清除、跨段复制粘贴、改变列表层级、增删表格行列、合并拆分单元格、改变图片布局、插入再删除文字、修改书签目标、接受或拒绝选定修订。记录真实步骤；不能随机点击后猜测预期。

接受和拒绝修订分别从同一个归档检查点建立分支副本，保留操作前带修订的版本。字段更新、目录更新和打印布局切换也记录为独立动作，避免缓存结果变化被误判为内核读取波动。

## 5. 高价值交叉场景

- 标题应用样式后，局部文字再加直接格式；样式继承与显式关闭格式同时存在。
- 一个段落内中英混排、emoji、超链接、不同字体、Tab 和手动换行相邻。
- 列表中插入普通段落后续编号；新列表重新编号；列表放入表格单元格。
- 横向节中的宽表、纵向正文、不同页眉页脚配置；修改“链接到前一节”状态。
- 表格有水平与垂直合并、单元格内多段落、重复标题行、不同边框底纹；嵌套表格以 UI 实际支持为前提。
- 同一图片重复使用、缩放、行内和浮动布局；检查资源复用与关系，不预设 Word 一定采用某种去重方式。
- 书签跨越格式边界；超链接到书签；交叉引用目标后续被编辑。
- 插入/删除修订覆盖局部文字或段落边界，批注锚定在带格式的文本附近；不假设 Word 支持所有范围重叠。
- 文本框、脚注、页眉中的文字与正文具有相同文本，检查读取来源与顺序，防止误合并。
- 修改目录标题后先保存未更新字段版本，再显式更新字段另存，分别说明预期缓存值。

每种组合至少有明确断言。通过增加有意义的交互提高复杂度，而不是单纯堆叠对象。

## 6. 查看项目读取效果的具体交付

每个检查点调用当前受测项目的真实读取入口，输出原始结果、规范化语义投影和诊断。若 CLI 尚不存在，沿用原交接建设驱动，不杜撰命令。

制作可阅读的读取报告，按锚点对照 Word 预期与内核实际值：正文、段落类型、样式、有效格式、列表、表格、图片、section、引用和不透明内容。报告展示层只呈现读取结果；不能补造解析器未返回的数据来制造“读对了”的效果。

如果已有可用编辑器集成，再在界面中检查展示，同时记录加载的内核版本。报告明确区分：Word 创建正确性、内核读取正确性、适配器输出正确性、编辑器呈现正确性。

内部 XML 采用独立解析器检查。缺少内核支持的领域记录 NOT_IMPLEMENTED，并测试原样保存保真；“保留成功”不等于“语义读取成功”。若 Word UI 实际行为不同于原计划，先记录并修正用例事实，不能无依据地改答案迁就内核。

## 7. 读取之后继续做保存和编辑回验

对每个检查点执行无编辑保存并检查整个文件字节一致；另对受支持的目标执行一次小编辑，验证非目标内容保真。把局部编辑后的 DOCX 交给 Word 打开，记录是否有修复提示、内容丢失或格式异常。

在综合文档中安排多种局部编辑，分别从固定原始副本开始，再增加连续编辑序列。涉及未支持操作时要求明确拒绝和状态不变，不强行绕过保护条件。

Word 再保存后的副本单独归档，用于语义互操作测试。内核字节保真在 Word 改写之前检查。必要时同环境导出 PDF 辅助观察，不能把因修改导致的合理重排算作损坏，也不能只凭页面看起来相同认定结构完整。

## 8. 失败定位与验收

发现失败时，先找最后成功检查点和第一个失败检查点，再缩小两者间的 Word 操作步骤。保留原始 Word 创建文件，另建最小复现；允许自动缩减生成辅助样本，但必须明确标记其来源与原 Word 样本不同。

沿用原交接的失败产物和结果分类。新增覆盖表需要区分：计划、Word 已创建、持久化结构已确认、内核已读取、断言通过、保存保真通过、Word 回验通过。任何一列未执行不能算全链路通过。

本增量的交付物：五个主题文档和一个综合文档的实际完成情况、各阶段 DOCX、操作 manifest、独立断言、读取报告、代表性截图、发现清单和复现步骤。功能不可用或有缺陷时如实交付差距，不为凑数量虚报完成。

大型语料和截图沿用目标仓库已有存储策略，报告链接到可访问产物并附哈希。不要在未检查体积和仓库约定的情况下把所有中间二进制文件加入 Git。来自 Word 的作者等元数据在对外分享前检查。

第一条增量进度汇报应说明：已接收本补充、当前测试版本、Word 可用能力、首个主题文档及综合文档的创建计划；随后优先做一个主题的完整创建到回验闭环，再批量扩展。
